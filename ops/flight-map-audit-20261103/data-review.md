## Документированные правила

Подтверждённых нарушений обязательных правил AGENTS/CLAUDE нет. Поводы для косметического рефакторинга по smell baseline не выдаются за дефекты. Нижеследующее — воспроизведённые риски реализации; оба унаследованы от v4, не регрессии 31cd0f14.

1. **P2: смена часового пояса блокирует весь корректный журнал.** `public/flight-map/v10/storage.js:22,30` вызывает проверку «не в будущем» при чтении уже сохранённых записей; `history.js:5–14` сравнивает дату с текущим локальным днём. На фиксированном времени `2026-11-03T02:00Z` запись HND→LAX с датой `2026-11-03` сохраняется и читается в Tokyo, но после перехода в Los Angeles `read()` падает `m143`, а любая запись — `m146`. Один перелёт делает недоступным весь журнал до смены дня; байты остаются целыми. Для авиаперелётов смена часового пояса — нормальный сценарий. Исправление: структурную/календарную проверку persisted данных отделить от ограничения будущего для нового пользовательского ввода. Сохранённые факты не объявлять повреждёнными из-за текущего часового пояса.

2. **Условный P2: fallback без Web Locks теряет одновременные изменения.** `storage.js:41–51`: `Promise.resolve().then(...)` сериализует только одну JS-среду. Воспроизведение использует два независимых Node worker как две вкладки, атомарные операции чтения/записи и барьер после чтения. Оба `writeAsync()` успешно завершаются, в хранилище остаётся один из двух новых рейсов. Современный путь `navigator.locks` этим воспроизведением не обвиняется. Исправление: для fallback использовать действительно транзакционное хранилище (например, IndexedDB) либо явно ограничить сохранение при отсутствии надёжной межвкладочной блокировки.

Воспроизведение обоих случаев: `node ops/flight-map-audit-20261103/data-repro.mjs` (Node22.23.2: обе проверки подтверждены). Скрипт не трогает пользовательский localStorage. Возможность потери данных без Locks доказана детерминированной моделью межвкладочного чередования; реальный старый браузер не тестировался.
