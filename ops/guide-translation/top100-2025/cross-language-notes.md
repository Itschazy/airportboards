## 1. Доказанный неполный контроль LTR для арабских телефонов

`ops/guide-translation/top100-2025/check.mjs` обнаруживает телефон только шаблоном `/\+\d[\d ()-]{5,}\d/g`. Он требует начальный `+`, поэтому не проверяет существующие номера:

| Файл / блок | Существующий телефон, пропускаемый regex |
|---|---|
| ar/SFO.json / taxi | *1107 |
| ar/PHX.json / wifi | 1-800-880-4117 |
| ar/IAH.json / wifi | 1-844-831-0999 |
| ar/YYZ.json / wifi | 1-866-207-1690 |
| ar/GRU.json / wifi | 0800-095-9026 |

Для каждого фактического блока этот regex вернул пустой список — проверено непосредственно. **Текущие пять номеров корректно окружены LRI/PDI**, поэтому это не пять текущих ошибок перевода. Доказанный finding — потеря этих изоляторов при будущей правке останется невидимой новому checker. Тот же вопрос касается возможных международных форм без `+` в будущих файлах.

Предложение родителю: при расширении checker учитывать телефонные вхождения, подтверждённые русским блоком, включая короткие служебные номера и национальные записи. Не ловить произвольную цепочку цифр как телефон — иначе время/цена даст ложные срабатывания. Сейчас правок скрипта не внесено.

## 2. Числовой сторож не доказывает привязку числа к цене/условию

В `scripts/check-guide-fresh.mjs` функция nums возвращает **Set** значений на hint+text целого блока. На реальном `en/FCO.json / transport` в памяти переставлены **€14 ↔ €40**; обе строки дали полностью одинаковый набор nums. Файлы не менялись. Это конкретная демонстрация слепого пятна: ошибочная цена обычного билета 40 и группы 14 не будет замечена именно числовым сравнением, хотя 14/40/56/4/32/15 все останутся в блоке.

Это **не ошибка текущего FCO**: действующие 14 за билет и 40 вместо56 за4 верны. Ограничение соответствует явно документированному назначению сторожа как проверки чисел, а не смысла. Аналогично он не распознаёт:

- currency `$` vs USD при неизменном значении;
- «до12 включительно» vs under12, оба содержат12;
- номер двери vs boarding gate при неизменном номере;
- 24 часа цены vs24 часа бесплатного хранения;
- 28 минут пути vs28 минут ожидания.

Смысловые проверки нужны по связкам **объект → условие → значение → единица → валюта**, а не ещё одна проверка множеств. Для будущей выборки ChatGPT приоритет: FCO transport, SHA storage (240/72/1), ATL lounges (3/2.5/2/17/18), EWR taxi (4/5/1) и YYZ transport (28/15/12.35/9.25/under12).

## Что дополнительный проход НЕ нашёл

- В новых европейских текстах не найдено запрещённых first floor / N. Etage / primer piso / planta N / N° piano / N. kat.
- Сопоставление валютных меток USD/EUR/€/$/£ не нашло расхождения текущего RU и текстов 11 языков.
- Полные SSID сохраняются; generic Wi-Fi→немецкое WLAN не считается утратой имени сети.
- Дополнительная проверка пяти национальных/коротких арабских телефонов подтвердила их нынешнюю LTR-изоляцию.
- Новых доказанных межъязыковых ошибок возраста, дверей, цен или бесплатности в этом целевом проходе не установлено. Уже исправленные случаи из предыдущих рецензий не выдаются за новые находки.

Первичные пробелы SHA T1 и GRU имени станции остаются задачей проверяющего источников; ни числовой PASS, ни этот проход их не закрывает. Текущие находки относятся к возможностям проверок, **не к доказанной дефектности всех 23 пакетов**. Следующий шаг — выборки ChatGPT по самым сложным связкам, а не объявление качества носителя по техническому PASS.
