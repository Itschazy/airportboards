## Что изменено и почему

Полный каталог аэропортов и общая гидратация Next задерживали появление карты. В v7 основной каталог содержит все имена, коды, страны и точные координаты, а дополнительные поисковые варианты загружаются отдельно. Для русского языка основной файл уменьшился с 213 182 до 125 408 Б gzip. Алиасы занимают ещё 69 375 Б; суммарная передача тоже меньше прежней. Все 6 074 аэропорта на 12 языках сохранены без потери значений, геометрия карты не менялась.

Серверный HTML запускает отдельный модуль карты раньше React. После гидратации React принимает уже работающий модуль: общий WeakMap предотвращает повторную инициализацию, AbortController снимает обработчики и отменяет работу при уходе со страницы. Ранние события проходят через прежний список разрешённых категориальных параметров; личная история в аналитику не передаётся.

Поисковый индекс строится порциями по 160 аэропортов. Первоначальная очередь через setTimeout оказалась непригодна в проверке Safari: через 28 секунд обработано только 1 600 из 6 074 строк, хотя данные уже разобраны, модуль смонтирован один раз и не отменён. MessageChannel устранил эту задержку, сохранив короткие задачи и закрытие портов при завершении или отмене. Ограничения таймеров также описаны в [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/setTimeout#reasons_for_delays_longer_than_specified).

До готовности полного поиска можно выбрать недавний аэропорт, ввести точный IATA или вставить маршрут CEK–AYT. При текстовом запросе есть переведённые сообщения ожидания и ошибки с повторной попыткой. Поздний ответ не открывает закрытую форму и не подменяет новый запрос. Enter выбирает только настоящий аэропорт, а не кнопку повтора.

В большом журнале миллионы километров выступали за колонку на 320 px. Теперь уменьшается только число, которое фактически не помещается. Обычные числа, дизайн остальных страниц, SEO, DNS и формат сохранённой истории не изменены. Опубликованные файлы v1–v6 оставлены без изменений.

При 500 сохранённых перелётах: карта готова за 3757 мс, CLS 0,000279, ошибок нет. Сразу отображаются 50 записей, остальные доступны через существующую пагинацию.

Полный сценарий с пустой историей на холодной сети: карта 4129 мс, первый текстовый результат 5254 мс от начала навигации, точный IATA около 2 мс, сохранение 152 мс, первая PNG 2209 мс. Получена картинка 1080×1920, ошибок нет. Этот сценарий не использован для чистых LCP/CLS: программное открытие картинки меняет кандидата LCP.

Проверка повышенного приоритета алиасов дала карту за 4107 мс и индекс за 4670 мс. Она отклонена, поскольку ухудшала первый экран. В итоговой версии приоритет алиасов пониженный.

Первые файлы before-2/3 недействительны: при переносе сборщика destination временно оставался v6. Исправлен путь, v6 восстановлена из HEAD, исходная серия полностью повторена (valid-before-1/2/3). Промежуточные boot-* и final-responsive не подменяют итоговую серию release1/2/3.

## Проверки поведения

- Chrome 375 px: холодное добавление Heathrow → LHR → CEK, сохранение и PNG; журнал 500 → 501.
- Chrome 320 px: поиск Чел → Челя → CEK → AYT, форма без горизонтального переполнения, закрытие, переход Настройки → Перелёты, сохранение 501 → 502 и восстановление после обновления. Ошибок в консоли не обнаружено.
- Большая статистика на 320 px: ширина и scrollWidth колонки километров равны 92 px, число уменьшилось до 18 px; остальные числа остались 25 px. На 375 px колонка 111 px, число 22 px.
- Safari macOS, японская локаль: задержка индекса воспроизведена и исправлена. Ручной поиск Heathrow, выбор HND, сохранение 6 → 7 и повторное открытие без подстановки тестовой истории сохранили семь перелётов. PNG и системное меню отправки с файлом 331 КБ работают; отмена возвращает активную кнопку. Адресату ничего не отправлялось.
- Автоматический повторный сценарий Safari с программным фокусом не засчитан за успех: индекс был готов за 157 мс, но фокус оставался в body. Поэтому поиск и сохранение дополнительно проверены вручную.

Это эмуляция слабого телефона и проверки настольных браузерных движков. Физические Android/iPhone, экранная клавиатура и отправка в социальные приложения на телефоне не проверены. Результаты не являются RUM.
