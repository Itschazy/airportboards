# Карта перелётов: медленные телефоны, 29.10.2026

Рабочая копия `/Users/whereiszhenya/projects/runwayboard-flight-map-prototype-20261028`, ветка `codex/flight-map-prototype-20261028`. База: опубликованный cfd54333, локальный документирующий eaddf92e.

## Причины и исправления

1. Холодный запуск ждал hydration → import app → девять зависимостей → каталог/географию. Runtime v5 собран в один ESM штатным webpack/terser из закреплённого Next 15.5.28: 33 569 байт, gzip около 12,7 КБ. Ленивый экспорт — отдельные 8481 байт, gzip 4018. Новых npm-зависимостей нет. Источники с комментариями сохранены; `scripts/build-flight-map-runtime.mjs --check` проверяет воспроизводимость generated bundles.
2. SSR карты заранее загружает runtime, каталог только текущего языка и географию. Эти ссылки отсутствуют на соседних страницах. Данные не скачиваются повторно при mount; это проверяется resource timing.
3. Закрытие любого sheet делало безусловный render/fit, даже если пользователь ничего не менял. Повторная валидация storage создавала новые объекты и сбрасывала масштаб. Теперь сравниваются фактические поля записей, включая порядок; межвкладочные изменения по-прежнему обновляют карту. После сохранения нет второго полного render из close.
4. Любой resize, включая клавиатуру, сбрасывал карту и пересоздавал журнал. Теперь меняется только геометрия при реальном изменении размеров контейнера; центр и ширина видимой области сохраняются.
5. Первый экспорт загружал флаги после завершения шрифтов. Они запрашиваются параллельно; неудачная загрузка шрифта может повториться на том же экземпляре экспортера. Очередь по-прежнему допускает один canvas и отбрасывает устаревшие результаты.

Старые runtime v1/v2/v3/v4 не изменены. Формат истории, словари, SEO-тексты, canonical/hreflang/FAQ/OG и sitemap не менялись. География/дизайн картинок не менялись. DNS и другие страницы не затронуты.

## Воспроизведение

Собственный локальный стенд, без ключа и production API. Browser API — CUA. Chrome DevTools: CPU 6×, Slow 4G, Disable cache. Сначала iframe375, затем прямой браузерный viewport iPhone SE375×667. Прокси3114/3115 подставляет одинаковый диагностический script в исходную/новую production-сборку и gzip; он не входит в продукт. Синтетическая история LHR→HND, личные данные не использовались.

Прежний код: closePreservesZoom=false, resizePreservesZoom=false. Новый код: оба true. Регрессионный тест экспорта с MAP_EXPORT_VERSION=v4 падает: флаги не запрошены до завершения шрифтов (0 вместо2); v5 проходит и повторную попытку после ошибки. Проверки выполняются на реальном экспортном коде, не на копии логики.

Первые iframe-прогоны: v4 ready7884мс/PNG2793мс; v5 только с preload, ещё без bundle, ready7000мс/PNG3045мс. Это не доказательство ускорения PNG. Из-за нестабильной повторной навигации iframe такие прогоны не смешиваем с финальным прямым сравнением. LCP родительской QA-страницы не используем как LCP карты.

Физические Android/iPhone и отправка реальному адресату не проверялись; CPU6× — лабораторное ограничение, а не модель конкретного телефона.
