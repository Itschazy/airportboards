# Локальный прототип «Мои перелёты»

Вопрос: какая компоновка лучше для мобильного пользователя — карта, журнал или паспорт?
Ветка prototype, не production. Отдельный статический стенд: Next-маршруты, SEO и платные данные не затрагиваются.

Запуск из корня репозитория:

```sh
python3 -m http.server 3102 --bind 127.0.0.1 --directory ops/prototypes/flight-map
```

Открыть http://localhost:3102/ru/my-flights-prototype/?variant=A
A — карта; B — журнал; C — паспорт. Переключатель снизу, клавиши ←/→.

Данные демонстрационные. Состояние в памяти, обновление страницы сбрасывает изменения.
Есть добавление/изменение/удаление с отменой, выбор аэропорта, дата/номер необязательны,
фильтр года, масштаб карты, светлая/тёмная темы, экспорт PNG900×1000.
Навигация других разделов — заглушки, не ссылки на production. Настройки меняют тему.
Это русский прототип: перед интеграцией нужны 12 переводов, полноценная клавиатурная
навигация combobox, сохранение/восстановление, реальная установка/мобильные проверки,
геодезические дуги/переход через180меридиан и продукционная обработка ошибок.

Inter и палитра — из текущего сайта e904f92e. Координаты/названия аэропортов — каталог проекта,
в демо ограниченная выборка. Береговая линия Natural Earth110m, public domain:
https://github.com/nvkelso/natural-earth-vector/blob/master/geojson/ne_110m_land.geojson
Дуги условные, расстояние — большая окружность между аэропортами, а не фактический трек.
Число стран означает страны аэропортов, а не факт въезда в страну.
