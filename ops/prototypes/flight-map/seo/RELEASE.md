# SEO / GEO / AEO: пакет подготовки карты перелётов

28.10.2026. Это локальная подготовка; публикации, отправки в поисковики и обещанного
трафика нет. Существующие страницы и элементы интерфейса не меняем.

## Что уже можно проверить

- `/ru/my-flights-prototype/`: новый сворачиваемый блок «О карте перелётов» под инструментом.
  Его текст есть в исходном HTML, без fetch/React/карты; на первом экране изменений нет.
- `/seo-preview/{locale}/`: 12 локальных страниц для вычитки переводов и мобильного QA.
  Это не дополнительные будущие SEO-лендинги: после интеграции пояснение живёт на самой
  странице работающего инструмента, без лишнего шага до добавления перелёта.
- `seo/{locale}.json`: title, description, инструкция, 6 вопросов и ответов, alt изображения.
  Переведены SEO-тексты, не весь интерфейс инструмента. Preview сообщает, что инструмент
  пока русскоязычный. 12 файлов имеют одинаковую структуру.
- `metadata.mjs`: будущие метаданные, self-canonical, взаимный hreflang, x-default,
  Open Graph/Twitter, JSON-LD WebPage+BreadcrumbList, чистый список URL для sitemap.
  По умолчанию всё noindex; передача releasedLocales без productReady вызывает ошибку.
- `assets/flight-map-demo.jpg`: 1200×630, фиксированный публичный пример с маркировкой
  DEMONSTRATION. Ни история браузера, ни даты/номера пользователя при создании не читаются.
- `render.mjs`: текст для исходного HTML с экранированием; нативные details/summary.
  `seo.css` ограничен новыми блоками. Старые CSS, кнопки, настройки и JS не менялись.

## Публикация после отдельного подтверждения

Планируемый единственный адрес инструмента: `/{locale}/flight-map` без query и trailing slash,
по каноническому стилю проекта. `/my-flights-prototype` и `/seo-preview` не публикуются.

1. В отдельной работе интегрировать инструмент в Next, сохранив существующие компоненты
   сайта. Публичная server page отдаёт нейтральный H1 и renderInfo; клиент загружает только
   собственный журнал. Не создавать отдельную обязательную посадочную страницу перед картой.
2. Для **фактически готовых** локалей вызвать `metadata(locale, copy, {releasedLocales,
   productReady:true})` из generateMetadata. Для неготовых — оставить noindex или404;
   не объявлять их через hreflang. 12 переводов SEO не означают готовность12 UI.
3. JSON-LD брать из `jsonLD(locale, copy, meta)` и вставлять через serializeJSONLD.
   Не добавлять вымышленные рейтинги, отзывы или «автоматический импорт билетов».
   FAQ/HowTo rich results не обещать; обычные ответы и инструкции уже присутствуют в HTML.
4. Публичную картинку скопировать в `public/images/flight-map-demo.jpg`, проверить200,
   image/jpeg и1200×630. В публичном OG никогда не использовать личный экспорт пользователя.
5. В app/sitemap.ts добавить только sitemapEntries для вышедших языков. lastModified
   ставить по реальному изменению контента, не Date.now() на каждый запрос. Для private,
   demo, export, restore и пустых share-идентификаторов никаких sitemap-URL.
6. Ссылку на карту добавить в подходящий существующий раздел после согласования
   размещения. Не переименовывать кнопки, не переделывать шапку/навигацию. Ссылка должна
   быть обычной `<a href="/{locale}/flight-map">` с понятным переведённым названием.
   Из новой страницы доступны главная/каталог через реальные компоненты сайта; не
   показывать прототипные заглушки на проде. Не добавлять ссылки на тысячи аэропортов.
7. Личная история остаётся в хранилище браузера. URL/hash, metadata, JSON-LD, серверный
   HTML и события аналитики не получают маршруты, даты, номера рейсов и backup-файлы.
   В публичном URL параметр ?demo не создаёт отдельную индексируемую сущность: canonical
   на чистый URL; только служебные/личные варианты получают noindex и не входят в sitemap.
   Если появится публичный профиль/ссылка истории, это отдельное согласование приватности.
8. Прогнать полноценную Next-сборку на фикстуре с пустым AIRLABS_API_KEY и проверки
   проекта, включая ключи12локалей, tsc, индекс, hreflang, live-refresh и AdSense.
   Проверить initial HTML без script/style и реально работающий инструмент у каждого
   indexable адреса. Нынешние тесты метаданных не подменяют этот шаг.
9. После разрешённого выпуска: audit-bot проверки200/canonical/robots/HTML/OG, Search
   Console URL Inspection и рендер Яндекса. Переобход — штатными проектными механизмами,
   не дублировать автоматическую квоту с локальной машины. Отправка ≠ индексация.

## Спрос и измерение

Фокус одной страницы: «карта моих перелётов», «создать карту перелётов», «дневник
перелётов», «карта перелётов бесплатно»; EN: personal flight map, flight log,
map my flights, flight history map. Это гипотезы по назначению инструмента и лексике
продуктов, а не измеренные частоты Wordstat/Keyword Planner. Live aircraft tracking
не обещаем: такой трафик приведёт пользователей с другим ожиданием.
Не создавать клоны страниц под каждую формулировку или комбинацию двух аэропортов.

После выпуска сравнивать сопоставимые28дней, отдельно mobile search, язык, браузер,
landing URL и buildId. В Search Console/Вебмастере: index status, impressions, clicks,
CTR и реальные запросы именно /flight-map. В Bing AI Performance — наблюдаемые цитаты;
не выдавать отсутствие данных за отсутствие показов во всех ИИ.

Подготовленные имена событий для интеграции с существующим lib/track.ts:
`flight_map_open`, `flight_map_first_saved`, `flight_map_export`,
`flight_map_backup`, `flight_map_restore`. Разрешённые параметры: locale, buildId,
export_kind(map/year/flight), format(story/square). Без городов, маршрутов, дат,
номеров, содержимого JSON, поисковых строк или идентификаторов перелётов. Событие
saved/restore — после успешной записи; export — после готового файла; native share
cancel не считается отправкой. Локальный прототип не отправляет эти события.

Конверсии: первый сохранённый перелёт / реальные пользователи страницы;
экспорт / пользователи с записью; повторные визиты. Боты отдельно. Ранжирование и
цитирование нельзя гарантировать. Специальный llms.txt, AI-текст и спрятанные ключи
не добавляются: для этого нет доказанной необходимости в данной функции.

Источники и актуальные ограничения: ../research/search-readiness.md.
