# Быстрое добавление и мобильный шеринг — 28.10.2026

Исследование для текущего улучшения карты перелётов. Runtime не менялся. Проверялись официальные документы и страницы продуктов; сообщения и публикации не отправлялись. Наличие приложения, реальная доставка PNG и поведение конкретных версий iOS/Android здесь не тестировались.

## Решение для AirportsBoard

Основное действие — **«Поделиться картинкой»**: заранее сформированный PNG передаётся через системное меню телефона. Рядом — **«Сохранить картинку»**, **«Скопировать подпись»**. Социальные кнопки ниже относятся явно к **ссылке**, а не к изображению. Пользователь должен заранее видеть разницу: ссылка открывает инструмент AirportsBoard, а личная карта остаётся на устройстве и передаётся картинкой.

Не делать шесть иконок, которые под разными названиями открывают одно системное меню без пояснения: это обещает выбор приложения, которого сайт не контролирует. Не включать скрытую загрузку личной PNG на сервер ради OG-preview. Не определять страну по языку/IP ради сокрытия кнопок: в русской версии можно первым рядом показать Telegram, MAX, Instagram, но остальные варианты должны оставаться доступными.

## Что позволяет браузер

[Web Share API, W3C](https://www.w3.org/TR/web-share/) задаёт `navigator.share({files, title, text, url})`, а выбор получателя оставляет браузеру/ОС. Поля конкретного приложения или режима Stories нет. Нужны HTTPS, пользовательское нажатие и доступная реализация API. `navigator.canShare({files:[file]})` проверяет именно файловую передачу: одной проверки наличия `navigator.share` недостаточно. Не все получатели принимают все поля; успешное завершение API не доказывает публикацию в соцсети. Отмена и отсутствие подходящих целей могут давать AbortError. `share()` расходует transient activation; [WebKit](https://webkit.org/blog/13862/the-user-activation-api/) объясняет, почему долгий await перед вызовом или второй защищённый вызов могут потерять пользовательский жест.

Практическое следствие: PNG готовим при открытии/изменении предпросмотра, кнопку активируем после готовности. Из tap вызываем `share()` непосредственно. Для картинки основной payload — `files`; подпись доступна отдельно, поскольку Instagram/другие получатели могут её отбросить. Не обещать «опубликовано» по resolve. Отмена сохраняет предпросмотр и не открывает автоматически альтернативную соцсеть.

На iPhone/Safari и Android/Chrome используем одинаковую проверку возможностей. Список приложений, наличие Instagram/MAX и выбор публикация/сторис зависят от установленного ПО. Не использовать таблицу версий браузеров вместо проверки текущего файла. При отсутствии поддержки остаются скачивание и копирование подписи.

## Социальные платформы

| Платформа | Подтверждённый web fallback | Что он действительно передаёт | Рекомендация |
|---|---|---|---|
| Telegram | `https://t.me/share/url?url=<encoded URL>&text=<encoded text>` | Ссылка и редактируемый текст, затем выбор чата/группы/канала | Отдельная кнопка «Ссылка в Telegram». Для PNG — системное меню |
| MAX | `https://max.ru/:share?text=<encoded text>` | Текст, в том числе ссылка. Официально iOS, Android и web; desktop в разработке | «Ссылка в MAX». Не передавать локальный blob URL как картинку |
| WhatsApp | `https://wa.me/?text=<encoded text>` | Предзаполненный текст без заранее выбранного телефона; пользователь выбирает контакт | «Ссылка в WhatsApp». PNG — системное меню |
| X / Twitter | `https://x.com/intent/tweet?text=<encoded text>&url=<encoded URL>` | Черновик поста со ссылкой/текстом, требующий решения пользователя | Link-only fallback, без автоматического PNG |
| Facebook | Официальный Share Dialog описывает передачу ссылки. Полная текущая документация недоступна (429) | Не считать локальный PNG вложением link dialog | В этом выпуске системное меню/скачивание. Не включать неподтверждённый shortcut под обещанием PNG |
| Instagram | Документация Sharing to Stories недоступна (429); подтверждённого web URL, принимающего наш File и выбирающего Stories, в исследовании нет | Открытие приложения само по себе не передаёт картинку | Кнопка-подсказка «Для Instagram»: системная отправка или сохранение картинки и загрузка в Instagram. Не обещать прямую публикацию |

Первичные источники:

- [Telegram — Sharing Button](https://core.telegram.org/widgets/share): официальный URL и URL encoding.
- [MAX — Диплинк для шеринга контента](https://dev.max.ru/docs/webapps/introduction): `:share?text=` и платформы. На этой же странице отдельный `shareMaxContent()` работает **из мини-приложения через бота**, это не API произвольного внешнего сайта. Встраивать MAX Bridge в обычную страницу ради ложного прямого PNG нельзя.
- [WhatsApp — How to link to WhatsApp from a different app](https://faq.whatsapp.com/425247423114725/): universal link с текстом, в том числе без номера. [Click to chat](https://faq.whatsapp.com/5913398998672934/?locale=pt_BR) дополнительно описывает выбор контакта для ссылки без номера.
- [X Help — Post button](https://help.x.com/en/using-x/add-x-share-button): редактируемый пост со ссылкой и отдельное пользовательское нажатие Post. [Официальный генератор X](https://publish.x.com/) выдаёт `x.com/intent/tweet`. Старый developer URL перенаправляется на общий docs.x.com/overview, поэтому не используется как доказательство актуального текста руководства.
- Meta: [Share Dialog](https://developers.facebook.com/docs/sharing/reference/share-dialog/), [Share Button](https://developers.facebook.com/docs/plugins/share-button/), [Instagram Sharing to Stories](https://developers.facebook.com/docs/instagram-platform/sharing-to-stories/) — все три дали HTTP 429; обход и повторные попытки не делались. Нативные SDK/URL schemes из сторонних статей нельзя выдавать за подтверждённую web-интеграцию. Facebook `sharer.php?u=` встречается в сторонних материалах, но актуальная официальная проверка этой формы в данном проходе не получена.

Все параметры URL кодировать отдельно. Не отправлять номера бронирований, точные даты, аэропорты или другие детали в link fallback без явного действия. Для ссылки по умолчанию достаточно короткой подписи и публичного адреса инструмента. Не включать сторонние SDK, пиксели или виджеты: обычные ссылки не добавляют загрузку соцсетей до нажатия.

## Аналоги: как ускоряют добавление

| Аналог | Что подтверждено первоисточником | Что перенять без платного API и лишних шагов |
|---|---|---|
| Flighty | Поиск по авиакомпании/номеру/началу маршрута; ручной ввод требует только вылет, прилёт и дату. Ручное добавление появляется для отсутствующего прошлого рейса | Наш ручной ввод оставить доступным сразу. Поиск города и кода в одном поле, необязательный номер убрать из обязательного пути |
| AirTrail | Минимум origin/destination/departure date; lookup номера дополняет данные; конфликт старого и fetched значения показывается пользователю; поддерживаются неполные даты | Не перезаписывать ввод без выбора. «Добавить обратный», «Ещё перелёт» и недавно выбранные аэропорты сократят повторные действия. Неполные даты — отдельная миграция модели, не подставлять фиктивный день |
| myFlightradar24 | Номер+дата автоматически заполняют детали при наличии рейса в базе; ручной подробный ввод и импорт OpenFlights | Номер без базы не должен изображать автопоиск. Быстрые готовые маршруты из личной истории полезнее формы с необязательными полями |
| FlightLog (пилотский, смежный продукт) | Для уже использованного номера могут предзаполняться маршрут и время; импорт показывает preview/дубликаты до сохранения | Повтор/обратный маршрут из собственной истории, явный preview перед импортом; не переносить сложность пилотского журнала в пассажирский инструмент |

Источники: [Flighty: Search/manual](https://flighty.com/help/using-search), [AirTrail: Add Flight](https://airtrail.johan.ohly.dk/docs/features/add-flight), [myFlightradar24: официальный рассказ о добавлении и импорте](https://www.flightradar24.com/blog/inside-flightradar24/flightdiary-becomes-myflightradar24/) (2017, описание механики историческое, не текущая проверка UI), [FlightLog: Create a New Flight](https://flightlog.io/docs/create-a-new-flight/), [FlightLog: Import](https://flightlog.io/docs-v3/).

Рекомендованный минимальный поток — «Откуда → Куда → дата (если известна) → Сохранить», с моментальными локальными подсказками; после сохранения — небольшой подтверждённый результат и быстрые «Обратный»/«Ещё». Если дата сейчас обязательна в модели, не ослаблять валидатор молча: отдельный видимый выбор неизвестной даты требует согласованного хранения/статистики/backup. Не назначать сегодняшнюю дату старому перелёту автоматически.

## Проверки перед заявлением готовности

- iOS Safari, Android Chrome/Яндекс: tap открывает системный chooser с PNG; отмена возвращает рабочий экран.
- Реальные установленные Telegram, MAX, Instagram, WhatsApp, Facebook, X: файл виден в composer и имеет правильный формат; **без публикации**. Если устройство недоступно — отметить, что доставка в конкретное приложение не проверена.
- Отсутствующее приложение/неподдерживаемые files: понятный download/copy fallback, без тупиков и самопроизвольных переходов.
- Кнопки link-only отделены от PNG; адреса с кириллицей, `&`, `#`, переносами кодируются правильно; приватные данные не попадают в URL.
- Share при быстрых переключениях года/темы получает последнюю картинку. Повторный tap не открывает несколько chooser. Ошибка/отмена не теряет сохранённые перелёты.
- Добавление на 320/375 px с клавиатурой: подсказки не закрыты, выбранный аэропорт устойчив при следующем символе, Back закрывает форму/поиск последовательно, duplicate предупреждается, обратный маршрут не копирует дату без подтверждения.

Ограничение: это исследование механизмов и проектные рекомендации, не отчёт о публикации или успешной отправке в приложения. Физические телефоны и авторизованные соцсети не использовались.
