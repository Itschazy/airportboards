## Как повторять

1. Production build/start на локальной фикстуре, `AIRLABS_API_KEY=` и отдельные
   `FLIGHT_STORE_PATH`, `AIRPORTSBOARD_DATA_DIR`, `NEXT_DIST_DIR` и при сборке, и при запуске.
2. Чистое окно Chrome инкогнито, открыть **только localhost**. В этой проверке окно
   открыто нативным UI; до аудита вкладка не подключалась к управлению расширением.
3. DevTools → Lighthouse → Navigation → Mobile → только Performance.
   Settings: Clear storage включён; **DevTools throttling (advanced)**.
   Simulated throttling — другая, расчётная методика; результаты не смешивать.
4. Три прогона одной сборки/фикстуры. Профиль Lighthouse 13.4.1: Moto G Power,
   412×823, CPU 4×, request latency 562.5 мс, download 1474.56 Кбит/с.
   Это лабораторная имитация, а не физический Android и не путь Т2.
5. Каждый отчёт сохранить как JSON через меню Lighthouse. Проверить LCP breakdown:
   элемент должен принадлежать табло; проверить отсутствие ресурсов расширений.
6. `node scripts/check-lcp-reports.mjs /absolute/actual-{1,2,3}.json`.
   Проверка намеренно привязана к AYT и одному профилю: другой LCP-элемент требует
   ручного разбора, а не автоматического принятия любого числа.

## Что установлено о production

Пять curl audit-bot с текущего компьютера: первый байт 0.78–0.91 с.
На самом сервере Next ответил за 33 мс, nginx с TLS — за 57 мс.
Это разные сетевые пути, не полевой тест Т2. Измерение указывает на существенную
сетевую составляющую; не доказывает причину каждого медленного посещения.
Задержка LCP 5.3 с в чистой локальной серии не воспроизведена.

nginx 1.24.0 поддерживал HTTP/2, но оба HTTPS-listen его не включали.
Сторож `node scripts/check-http2.mjs` воспроизвёл ошибку: `1.1 !== 2`.
Исправление меняет только два listen, включает согласование h2 и сохраняет HTTP/1.1.
Содержание страниц, gzip, кэш, маршрутизация, TLS-сертификаты, данные и DNS не меняются.

Проверка/применение на сервере от root:

```sh
python3 ops/enable-http2.py          # только diff
python3 ops/enable-http2.py --apply  # backup, nginx -t, reload, проверка h2
```

Скрипт предназначен для существующего nginx 1.24. После обновления nginx
пересмотреть синтаксис: отдельная директива `http2 on` появилась в 1.25.1.
Документация: https://nginx.org/en/docs/http/ngx_http_v2_module.html
Первый немедленный probe после graceful reload успел попасть в старый worker,
поэтому сработал откат. Проверка теперь ограниченно ждёт новые workers;
при ошибке конфигурации, reload или живого h2 всё равно восстанавливает backup.

Для ручного отката скопировать указанный скриптом backup на место
`/etc/nginx/sites-available/airportsboard`, затем `nginx -t` и
`systemctl reload nginx`. Backup находится вне подключаемых каталогов nginx.
Пуш приложения сам по себе nginx не меняет: применение скрипта — отдельный шаг.

Десять одинаковых initial JS файлов (137181 Б gzip): HTTP/1.1 — 6 соединений,
HTTP/2 — 1 соединение. Время на текущем сетевом пути колеблется; это не доказанный
процент выигрыша LCP. Не приписывать HTTP/2 локальные 0.81 с: localhost измерялся
без production nginx, а приложение в этом изменении вообще не менялось.

После применения: `check-http2`, `check-index`, `check-sitemap-hreflang`,
`check-live-refresh`, `check-adsense`, `check-first-paint`.
Все production-запросы этих проверок используют audit-bot и не покупают рейсы.

Отдельная серия без параллельных проверок (3 запроса каждого протокола,
чередование H1/H2/H2/H1/H1/H2): медиана доставки этих десяти JS файлов
1.615 с по H1 и 1.381 с по H2. Это небольшой лабораторный сетевой тест с этого
компьютера, не LCP и не измерение смартфона. Сырые результаты:
`delivery-isolated.json`; ранняя `delivery-after.json` снята параллельно со
сторожами и не используется для сравнения скорости.
