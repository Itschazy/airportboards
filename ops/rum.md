# Реальный LCP: браузеры и версии выката

Сбор разрешён владельцем 24.10.2026. Цель — найти этап медленных первых загрузок,
а не принять лабораторный Lighthouse или timing Метрики за пользовательский LCP.

## Что измеряется

`WebVitals` после гидратации загружает отдельный chunk `web-vitals/attribution` 6.2.3.
Буфер PerformanceObserver сохраняет ранние записи. Миниатюрный inline bootstrap
до гидратации запоминает исходный путь, первое скрытие и возврат из BFCache.
Логика не меняет UI, CSS, SSR-контент, schema, canonical, DNS и свежесть рейсов.

Одна запись после финализации LCP библиотекой (первое взаимодействие/скрытие).
Нет повторов и фонового опроса. При закрытии страницы используется keepalive fetch.
Сетевые ошибки проглатываются. SPA, BFCache и prerender в отчёт первой загрузки
не входят; `navigate`, `reload`, `back_forward` группируются отдельно.
Не путать `navigate` с гарантированно пустым HTTP-кэшем: API этого не доказывает.

В каждой записи: SHA исходного клиентского JS (12 символов, зафиксирован **при
сборке**, а не взят из текущего HEAD сервера), семейство и major браузера,
mobile/tablet/desktop, Android/iOS/other, грубые network/deviceMemory,
локаль/код аэропорта/тип страницы; LCP, FCP, TTFB и фазы атрибуции LCP,
DNS/connect/request/HTML, длинные задачи до LCP, ограниченная сводка ресурсов.
Элемент LCP — только категория heading/flight-row/text/image/video/other.
Час записывается сервером в UTC; время посещения до секунды не сохраняется.
Полного UA, IP, query, номера рейса, referrer, URL ресурса, CSS-селектора,
текста страницы, metric.id и идентификатора пользователя в **RUM-файлах** нет.
Обычные технические логи nginx — отдельная существующая система.

## Ограничения выборки

- Только production apex/www, главная и табло. Localhost допускается лишь в
  специальной локальной сборке `NEXT_PUBLIC_RUM_LOCAL_TEST=1`, сервер дополнительно
  требует `RUM_ALLOW_LOCAL=1`. В production этих флагов нет.
- Сохранены отказ `ab_consent_v1=denied`, DNT/GPC, региональная политика по часовому
  поясу (как Метрика), исключения автоматизации. Неизвестный пояс/storage — пропуск.
  Явное granted разрешает регион; DNT/GPC всё равно имеют приоритет.
- Нужны LCP PerformanceObserver, Array.at/findLast; старые браузеры пропускаются.
  Safari без LCP API не даёт нулевые значения. Из Safari с API данные будут поступать.
- Первый экран до гидратации мог быть виден, даже если JS не загрузился и замера нет.
  Блокировщики, закрытие до инициализации, offline и аварии дают потерю доставки.
  Поэтому число записей не равно всем посетителям Метрики.
- Long Tasks есть не везде: `-1` значит неизвестно, не 0. Буфер 512 записей,
  переполнение отмечено. `scriptBytes` — transferSize завершённых до LCP ресурсов,
  может быть 0 из-за кэша/cross-origin; это НЕ полный вес JavaScript сайта.
  Буфер Resource Timing браузера ограничен; сводка — вспомогательное свидетельство.
- Самый долгий ресурс не обязательно блокирует LCP. Фазы LCP — основной ориентир.
  Сумма/разность перцентилей фаз не равна фазам «типичного» визита.
- Группы n<50 явно помечены предварительными; сравнивать одинаковые страницы,
  браузеры, устройства, навигацию, периоды и достаточную выборку. Процентили
  не доказывают причинность. Для окончательного диагноза нужен профиль устройства.

## Хранение и чтение

`$AIRPORTSBOARD_DATA_DIR/rum`, по умолчанию `~/airportsboard-data/rum`.
Каталог 0700, файлы 0600. Фиксированное кольцо 14 дневных слотов × 8 PM2 slots ×
1 МиБ = максимум 112 МиБ плюс маленькие lock-файлы; при трёх worker максимум 42 МиБ.
Обычно файл заменяется новыми диагностическими данными через 14 дней; неактивный
слот может хранить старый файл до следующего использования. Отчёт ограничен датами.
Никаких изменений flightStore, архива рейсов, ISR-кэша и секретов.
При заполнении файла замеры отбрасываются до следующего дня; отчёт предупреждает
о файлах, которым осталось меньше максимального тела запроса (4 КиБ).
Общий предел приёма 120 запросов/минуту/процесс; при reload счётчик начинается заново.
Межпроцессный lock защищает перезапуск worker. Недоступная диагностика не мешает табло.

`POST /api/rum` проверяет Origin, потоковый предел тела 4096 байт и строгую схему;
ответ no-store/noindex. Публичного GET/чтения нет. Origin не аутентификация:
подделка извне возможна, поэтому нужны лимиты и осторожность к выбросам.
Аварийная остановка записи: `RUM_DISABLED=1` в окружении PM2 с обычным обновлением
окружения процесса. Не менять env/перезапускать без необходимости.

На сервере из `/var/www/airportsboard`:

```bash
node scripts/report-rum.mjs --device=mobile --locale=ru
node scripts/report-rum.mjs --device=mobile --platform=android --browser=chrome --json
node scripts/report-rum.mjs --device=mobile --minLcp=4000 --json
node scripts/report-rum.mjs --device=mobile --browser=yandex --by=release,browserMajor,page,navigation --json
node scripts/report-rum.mjs --since=2026-10-24 --until=2026-10-26 --airport=AYT --json
```

По умолчанию последние 7 календарных UTC-дней. Можно указать `--dir=/path/to/rum`
для локальной копии. Подключение к Airlabs/Метрике/Google не нужно.
После выката проверить SHA сервера/CI, обязательные SEO/freshness guards,
приём естественных визитов и `report-rum`. Синтетические browser-UA запросы на
production запрещены; `audit-bot` намеренно игнорируется и не портит выборку.

Проверки: `node scripts/check-rum.mjs`; production fixture build с пустым ключом;
проверка браузером 375 px, локальная фактическая запись; HTTP Origin/размер/GET;
`check-first-paint`, `check-analytics-loading`, 12 локалей, стандартные guards.
