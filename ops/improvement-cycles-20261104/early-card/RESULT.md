# Запуск 8/20: первое нажатие до загрузки React

База: b3f6e2e833b9de08209f3248400ea13b7ca1b4d9 (продукт как production870f52bc).
Рабочая копия /Users/whereiszhenya/projects/runwayboard-flight-map-prototype-20261028.

## Воспроизведение и причина

Production build на фикстуре с пустым ключом, Next на3159. Локальный proxy3160
показывает реальную страницу AYT в iframe375×812 и удерживает только Next JS chunks.
WebKit: видны20SSR-строк,6запросовJS ждут; одно настоящее нажатие SU112(isTrusted=true),
после release все10чанков получены, карточки нет. Второе нажатие открывает SU112.
Это конкретная потеря события в окне до React, не доказательство низкого LCP/INP.

Проверялись три причины: ещё нет обработчика, сброс выбора эффектом, замена строки.
До чанков обработчика React действительно нет; после запуска выбор остаётся null.
На этом сценарии нет query-flight/switchMode, которые могли бы сбросить выбор.
Раннее нажатие до установки React не попадает в его механизм event replay.

## Исправление

lib/board-intent.ts: inline-bootstrap перед строками, только на табло. Хранит
последний выбор в памяти документа, привязанный к DOM-борту, URL, номеру и времени
рейса; никаких сетевых запросов/Storage/новой разметки интерфейса. Перед готовностью
capture останавливает событие, исключая второй React replay. Первый mount забирает
намерение, снимает обработчики и открывает обычную карточку. Другой клик/клавиша,
pagehide, смена URL/борта или возраст>60с отменяют выбор. Живое нажатие важнее
параметра старой ссылки ?flight. Действующая ссылка без раннего нажатия проверена.

preventDefault до гидратации отменяет и стандартный фокус, поэтому bootstrap
явно фокусирует строку без прокрутки. Проверено после реального release по CLI:
закрытие карточки возвращает фокус на SU112. Нажатие внешней кнопки Release
в родительском iframe-стенде переводит фокус в другой документ: этот вариант
не является проверкой восстановления фокуса реальной страницы.
