# Запуск 1/20 — большие карты, 04.11.2026

База ca0720ab; origin/main после fetch остаётся 9a0dc1ab. Профиль Node на Mac,
не Android/LCP: 4999 разных маршрутов — SVG 12 966 571 байт, 30 032 элемента,
body ~138 мс (с профилировщиком). Перед изменением сохранён исходный модуль.

Гипотезы по профилю, в порядке приоритета:
1. Форматирование 49 точек каждой линии и разбор этих линий создают лишнюю
   нагрузку. Если убрать только субпиксельно избыточные точки больших сетей,
   объём SVG и CPU уменьшатся, геометрия останется в измеряемом допуске.
2. Проверка пересечений подписей сканирует слишком много сегментов. Пространственный
   индекс ускорит onRoute, но не уменьшит размер SVG и стоимость DOM.
3. Cache на 512 дуг при тысячах маршрутов вытесняется до повторного использования.
   Расширение даст выигрыш CPU, но увеличит удерживаемую память; не первый выбор.

Первый эксперимент: упрощать только сериализуемую линию в истории >100 уникальных
маршрутов, не исходные геодезические дуги, bounds, расстояния, точки аэропортов,
отбор подписей или статистику. Граница ошибки — доли пикселя. Для обычных карт
полный строковый результат должен остаться прежним. Отрицательный defs/use
эксперимент 03.11 не повторяется. Без доказанного выигрыша изменение не сохранять.
