# Запуск 6/20: стресс-профиль и исправление редиректов аэропортов

## Исправленная проблема

При повторной проверке production build на локальной фикстуре `/en/airport/jfk`
отдавал 308 без Location (`x-nextjs-cache: HIT/STALE`). Первый запрос проходил,
повторный check-index давал 19/20. Запрос с query мог отдавать 200 вместо HTTP
редиректа. На production в момент проверки дефект НЕ повторился: Location присутствовал.

Нормализация трёх видов страниц табло перенесена перед ISR в middleware.
Существующие permanentRedirect в страницах сохранены как страховка. Нижний регистр
и переименованный код теперь ведут сразу на актуальный URL: `tse` → `NQZ`, один
308 вместо двух. Query сохраняется. Никаких изменений данных рейсов, локалей,
дизайна, DNS или контента. Неизвестные вложенные пути не перенаправляются.

Найден дефект самого check-index: переданный позиционный localhost игнорировался,
скрипт проверял production. Теперь явный URL имеет приоритет над BASE; неверные
аргументы останавливаются до сети. Первый случайный production-аудит был безопасным
(audit-bot, без API рейсов) и дал 20/20; его нельзя считать локальной проверкой.
