## Что исправлено и почему

Аудит 03.11 воспроизвёл потерю одного перелёта: два независимых worker-контекста
без Web Locks одновременно читали старый localStorage, обе записи сообщали
успех. Сравнение старого и нового значения не делает пару getItem/setItem
атомарной. Это отдельная причина от уже исправленного захвата observed перед
ожиданием и от логики слияния импорта.

Добавлена резервная блокировка через readwrite-транзакцию IndexedDB с общим
object store. Синхронные чтение, проверка и запись исполняются внутри success
запроса после получения блокировки. Основание — [порядок транзакций в спецификации
IndexedDB](https://www.w3.org/TR/IndexedDB/#transaction-scheduling).
Все async-пути сохранения, импорта и отмены импорта используют её. Web Locks
остаётся основным механизмом. Без обоих API запись отклоняется с существующей
локализованной ошибкой; небезопасного Promise-fallback больше нет.

Журнал не мигрирует: прежние ключ, JSON-формат и localStorage сохранены. IndexedDB
не хранит перелёты, открывается только при записи и только без Web Locks.
Первое чтение и первый экран не ждут её. Соединение закрывается после операции,
ошибки и тайм-аута 8 секунд; поздний open после тайм-аута не может записать данные.
Дизайн, DNS, справочные, SSR-тексты и SEO не менялись. Новых переводов не требуется.

## Ограничения и очередь следующих запусков

1. Защита относится к обновлённым вкладкам. Уже открытая старая версия без
   блокировки не становится безопасной задним числом. Синхронный store.write —
   внутренний примитив; UI должен продолжать пользоваться только async-методами.
2. localStorage и IndexedDB не образуют общую транзакцию. Если браузер оборвёт
   IDB-транзакцию уже после setItem, возможна ошибка при фактически сохранённой
   записи. Перечитывание истории/идемпотентный импорт безопасны; не обещаем rollback.
3. Следующий приоритет — большие карты/экспорт (1000–5000 записей), измерение
   объёма SVG, CPU и памяти до/после. Не повторять неудачный defs/use-эксперимент
   из аудита 03.11 без новой гипотезы.
4. Проверить JSON-восстановление после западной смены часового пояса: чтение
   исправлено, строгий импорт сохранённой даты пока может отказать.
5. Повторить первый экран/поиск с сохранённой историей в мобильной матрице;
   не заменять реальный слабый Android настольными таймерами.
6. Для SEO/GEO/AEO: актуальные кабинеты Bing/GSC/Метрики, проверяемые проблемы
   индексации/посадочных/интентов. Новые факты справочной — только по источникам,
   новые строки сразу на 12 языках, без шаблонного раздувания текста.
7. Эффект выката 03.11 на отказы/воронку оценивать после 7 полных дней,
   на том же сегменте смартфонов из поиска и с разбивкой браузер/страница/версия.
   До этого сравнение помечать предварительным. AdSense уже на рассмотрении,
   повторно заявку не отправлять.

Новые пакеты готовить с доказательствами для владельца. Не переносить разрешение
