# IndexNow v2 — подготовлено, не установлено

Причина: старый отправитель отмечал весь набор успешно отправленным, если прошла хотя бы одна партия. Теперь sent меняется только для принятой партии. 200/202 — приём уведомления, НЕ доказательство индексации. Официальный протокол: https://www.indexnow.org/documentation . Участники делятся уведомлениями; второй endpoint используется только при отказе первого. На 429 fallback не вызывается.

## Поведение

- 50 URL в POST, максимум100 за запуск. Ошибка останавливает текущий прогон; повтор через10 минут, далее20,40… до суток. Успешные партии не повторяются. При crash между POST и сохранением допустим повтор, потеря очереди недопустима.
- JSON вне git clean: /home/deploy/airportsboard-data/seo/indexnow-v2.json. fsync+rename, режим600; повреждённое состояние останавливает отправку, а не обнуляет его.
- Оба режима делят flock с обслуживанием build-cache. Занятый lock — пропуск, не ошибка. Источники HEAD, build manifest и SHA работающего /api/health должны совпасть. Проверка не делает запросов к API рейсов.
- `--dry` полностью локален, ничего не записывает и не отправляет. Обычная отправка разрешена только Linux, /var/www/airportsboard.
- Источники изменений: справочные/переводы/дата проверки, шаблон и сообщения аэропорта, события и их статус, SEO/тексты карты перелётов. Живые рейсы и время сборки не хешируются. Это не универсальный детектор любого пикселя/изображения сайта.
- Старый ежедневный вызов совместим: дополнительно читает sitemap (общий бюджет30с), сохраняет обнаруженные URL. Worker только обрабатывает контент/очередь. Снятие из sitemap не означает удаление страницы; автоматических delete-уведомлений нет. При удалении страницы нужна отдельная явная редакционная миграция.
- /departures не отправляется повторно: canonical родителя. Сами URL/редиректы/robots не меняются.
- Приоритет: выбранные по Bing аэропорты → содержательные изменения уже известных страниц → первоначальное обнаружение остальных адресов. Новая правка не ждёт за всем первичным каталогом.
- На первом запуске v2 все4548 контентныхURL считаются новыми (до discovery); старому sent нельзя доверять из-за бага. Дренирование постепенно, не массовый залп. Discovery дополнительно добавит адреса из карты; фактическое число видно в state/runs. После этого неизменившиеся страницы не отправляются ежедневно.

## После явного разрешения на выкат

1. Push main вне окон прогрева, дождаться success Actions, сверить SHA и /api/health audit-bot. Пройти штатные post-deploy проверки.
2. На сервере проверить `command -v node` и существующее расписание IndexNow. Не создавать второй worker, если он уже есть. Daily оставить.
3. Проверить `systemd-analyze verify` для двух unit-файлов. Создать /home/deploy/airportsboard-data/seo с владельцем deploy. Установить units в /etc/systemd/system (0644), daemon-reload, enable --now airportsboard-indexnow.timer. Если node не /usr/bin/node — указать проверенный абсолютный путь.
4. Первый запуск: systemctl start airportsboard-indexnow.service. Проверить journalctl и state: accepted>0, pending уменьшается; 202 отдельно от факта появления в индексе. Не печатать ключ/секреты. Снять второй dry: неизменившееся содержимое не возвращается в очередь.
5. Проверить timer и после следующего тика убедиться, что отправлены следующие URL. Bing IndexNow History подтверждает доставку с задержкой кабинета; результаты индексации отдельно.
