# Первый экран табло: скачок условной высоты строк

08.11.2026, серия airportsboard-8, запуск 4. База 0223364a / runtime 815101aa.

## Причина и изменение

При 375×812 видимые `.frow` сначала занимали `contain-intrinsic-size: auto 72px`,
затем переходили к реальным 81.65625 / 99.9375px. Chromium LayoutShift связывает
основной скачок DXB с LI, высота и положение которых менялись сразу после первого
кадра. Повтор исходного DXB дал тот же CLS 0.03837.

Проверяемые гипотезы: content-visibility; загрузка шрифта; гидратация/обновление
снимка. Менялась только CSS-видимость первых 12 строк. Данные, JS, шрифты и остальной
CSS одинаковы. В 12 чередующихся A/B парах скачок заметно уменьшился на всех четырёх
страницах. Затем тот же результат проверен на настоящей пересборке, без CSS-подмены.
Остаточный CLS BCN пока не диагностирован; не объявляем его подтверждённой проблемой
шрифта. Это отдельный следующий шаг.

Первые 12 строк рассчитываются сразу, начиная с 13-й остаётся auto. Почему 12:
запас на первый экран телефона и более высокий экран, без снятия ленивой отрисовки
со всех 30/80 строк. Фиксированной высоты нет; текст, переносы, визуальный дизайн,
семантическая разметка, данные, SEO, DNS и переводы не меняются.

## Протокол и ограничения

Десктопный встроенный браузер, фактический UA Chrome/155.0.0.0 на Mac, 375×812.
**Это не Safari/WebKit и не физический Android.** В прошлых отчётах IAB назван
WebKit без доказательства движка; те функциональные проверки не доказывают Safari.
В этом запуске Chrome extension единожды отказал timeoutMs; попытки не повторяли.
CPU/сеть не замедлялись. Ресурсы прогреты; это не холодный первый визит из интернета.

Исходная фикстура расширена BKK/DXB/BCN/DOH по 240 синтетических строк на направление,
без ключа. Next отдаёт 80, первоначально DOM показывает 30 — не 240 DOM-строк.
Локальный loopback proxy 3176→3177 буферизует HTML и вставляет ранний диагностический
PerformanceObserver. Метрики отправляются только локально. Это влияет на TTFB и
потоковую загрузку: абсолютные скорости не переносятся на production.
CLS измерен через 1 секунду после load, без пользовательского ввода; не CLS всего
визита. FirstRows — два requestAnimationFrame после появления строк, не замена LCP.

`paired.json`: по 3 A/B пары на страницу (AB, BA, AB), затем actual build по 3
загрузки. Цифры ниже — исходные A из пар и настоящий новый build. Во всех 24 парных
снимках ширина 375, горизонтального переполнения нет, 30 строк, конечная геометрия
первой строки совпадает до/после. В 12 новых build-замерах нет longtask >50ms.
