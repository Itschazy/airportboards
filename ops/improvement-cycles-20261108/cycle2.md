## Причина и изменение

В поиске карты каждый непустой запрос склеивал code/city/name/latin для всех
6074 строк. Состав строки неизменен. Теперь indexedRow готовит hay один раз
в тех же порциях асинхронного индекса (800 аэропортов), поиск переиспользует его.
Порядок полей, нормализация, сортировка, recent/exclude/limit не меняются.
Это небольшое ускорение набора текста, НЕ объяснение многосекундного LCP.
Интерфейс/тексты/данные/SEO/DNS не менялись; runtime пересобран штатным скриптом.

Три изолированные проверки: cached hay сокращает RU batch 21.64 → 9.42 мс;
убрать сортировку:20.43 мс, убрать normalize:21.81 мс. Последние две — только
выброшенные диагностические варианты, в продукт НЕ переносились.
Node измерения не называем Android LCP. Полный каталог и запросы одинаковы.
