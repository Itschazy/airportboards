## Измерение

По отдельному разрешению владельца добавлены 13 JS-целей в счётчик 110112198. У каждой `type=action`, точное совпадение идентификатора из lib/track.ts. Прежняя автоцель формы осталась неизменной: всего 14 целей. Повторный dry-run: добавить 0.

- Manifest: goals.json. Документация API: https://yandex.ru/dev/metrika/ru/management/addgoal-example
- `python3 scripts/metrika-goals.py` — только чтение и сверка.
- `--apply` — только после явного разрешения владельца. Повторный запуск сначала читает цели; дубликаты/конфликты останавливают запись. При неоднозначной ошибке POST не повторяется автоматически.
- `--output /absolute/report.json` сохраняет только цели, без токена. Авторизация из `~/.env.yandex-metrika` или переменной окружения.
- Протестированы отсутствие цели, уже существующая цель, дубликат, конфликт имени и типа/условия. `check-track` проверяет безопасную отправку событий. Живые события не имитировались, прод в браузере не открывался.

Новые цели не восстанавливают прошлую статистику. Сегмент для будущего сравнения: ru, смартфоны, поиск; отдельно browser и startURL. Открытие карты не равно сохранению, экспорт не доказывает публикацию в соцсети. GA4 по другим языкам нельзя смешивать с русской Метрикой.

## Локальная проверка

`mobile-check.html` — только локальный диагностический стенд, не часть сайта. Для повтора скопировать его в `public/__audit-mobile.html` перед запуском сервера на фикстуре без ключа, открыть localhost и удалить копию после проверки. Он показывает реальную страницу в iframe 375/320/414 px, позволяет открыть карточку обычным нажатием и проверяет геометрию значений. Запуск без открытой карточки с плитками даёт FAIL, а не ложный успех. Старый баг воспроизведён на «1 ч 30 мин»; после исправления полный текст помещается или переносится.

Это проверка адаптивной вёрстки, не эмуляция слабого CPU/сотовой сети и не физический iPhone. Отдельно проверен настоящий Safari на Mac с тем же узким кадром.
