# Независимая заключительная рецензия — 03.11.2026

Проверены активный `public/flight-map/v9/app.js`, оболочка `shell-i18n.json`, CSS страницы карты и модули v10 history/storage/transfer/map/share. Браузер недоступен; ниже code review и Node-проверки, не выдаваемые за тест Safari или реального телефона.

## Исправленные дефекты

- **P1, сохранность данных:** `store.writeAsync` раньше сравнивал текущий localStorage с изменяемой переменной `observed` после ожидания Web Lock. Если перед старым сохранением формы выполнялся импорт на том же store, импорт продвигал `observed`, а устаревшая форма успешно удаляла новую партию. Новый тест `queued stale save cannot overwrite import that advances same store observed value` первоначально упал с Missing expected rejection. Исправление в v10/storage фиксирует ожидаемый снимок до постановки в очередь; тест проходит. Parent UI не менялся.
- **P1, demo:** повторная проверка подтвердила переключение на personal при обратном/следующем перелёте. Создание пользовательской записи больше не остаётся в демо.
- **P2, async UI:** успешная ветка импорта теперь закрывает окно только при совпадении revision. Во время операции поля заблокированы.
- **P2, undo:** удалённый последний год и выбранный удалённый рейс очищаются после отмены партии.
- **P2, поиск:** добавлены airport.name обоих аэропортов, поэтому названия аэропортов участвуют в поиске журнала.

## Передано parent на заключительное исправление

- **P2, CSS checkbox:** правило `.check-option input` задаёт height 20, но наследует min-height 50, padding 13px 15px и margin-top 7px от общего input. Нужны явные min-height/padding/margin для compact checkbox; иначе touch UI растягивается.
- **P2, поздняя ошибка:** catch подтверждения импорта и file.text должны проверять revision/signal так же, как успешный результат. Иначе ошибка старого закрытого окна может появиться в новом.

В этом проходе нет доказательства быстрого отображения 5000 уникальных маршрутов. Поиск журнала не перерисовывает карту на каждую букву, CSV-парсер и экспорт загружаются по требованию.

## Исследованная оптимизация большого журнала — вне текущего пакета

По решению parent эксперимент `defs/use` НЕ внесён в production-исходник v10/map.js. Цель: вместо трёх копий одинакового `d` (ореол, линия, hit-target) держать одну геометрию в defs и три use с прежними классами. На path в defs явно задан `vector-effect="non-scaling-stroke"`; координаты, подписи, порядок линий и data-route не менялись.

Проверены 18 карт (320/375/1080 px, обычный/выделенный маршрут, Европа/Тихий океан/мировая сеть) и 12 вариантов экспорта (story/square/4:5, карта/один рейс, светлый/тёмный). `rsvg-convert` дал **30/30 строго одинаковых RGBA-буферов** до/после, без допуска. Это проверка другим SVG-движком, а не Safari/Chrome; касания и shadow-tree hit-targets браузера не проверялись.

Повторный единичный замер 4999 уникальных маршрутов:

- до: SVG 13 094 977 байт, fit 66 мс, body 195 мс;
- эксперимент: SVG 6 685 973 байт, fit 66 мс, body 185 мс;
- размер строки уменьшен примерно на 49%, CPU генерации практически не изменился; узлов и SVG shadow instances становится больше. Ускорение браузерной отрисовки из этих цифр не следует.

Прототип before/after и четыре контрольных PNG сохранены в `outputs/flight-map-improvements-20261103/svg-use-prototype/` рабочей копии. Следующая отдельная задача: сравнить DOM/paint/memory и hit-targets в Safari и Chrome на локальной фикстуре, включая слабый Android; только после этого решать о внедрении. Сохранность импортированных данных и прежних endpoint-маркеров отложенной оптимизацией не затрагивается.

Основания реализации: MDN [use](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/use) (клонирование поддерева и наследование стилей), [vector-effect](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/vector-effect). Проверено 03.11.2026.
