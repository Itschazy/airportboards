## Оставшиеся риски — аудит не даёт заключения «без багов»

**P1, условный: две вкладки без Web Locks.** Изолированный воспроизводимый тест двух JS workers подтверждает: обе операции могут сообщить успех, последняя перезапишет первую. Сравнение localStorage getItem/setItem не атомарно. Web Locks-путь покрыт существующими тестами, но fallback не даёт той же гарантии. Скрипт `node ops/flight-map-full-audit-20261103/fallback-race.mjs` завершается успехом при подтверждении дефекта, это не зелёный регрессионный тест! Для устранения нужен транзакционный fallback (например, IndexedDB) с проверкой миграции, конфликта, quota и отмены импорта; быстрый localStorage-lock не внедрялся.

**P2: тяжёлая большая карта и перегруженный экспорт.** При 1000 разных маршрутов SVG ~2,91 МБ, при 4999 ~12,97 МБ; журнал показывает 50 записей, но все линии карты остаются в DOM. На скачанном PNG из 1021 синтетического перелёта подписи тесные, часть близка к краям, карта превращается в плотную сетку. Для обычной истории из нескольких перелётов это не воспроизводится. Следующий шаг — уровни детализации и отбор подписей с проверкой сохранения всех маршрутов/цифр.

**P2: внешний backup после перелёта на запад.** Существующая история теперь читается, но восстановление JSON с датой, которая в новом часовом поясе ещё «завтра», всё ещё отклоняется строгим импортом. Нужна отдельная политика для подтверждённой истории и неизвестных файлов.

**Границы шейринга.** Все кнопки брендов открывают одно меню ОС; сайт не выбирает приложение-получатель. Реальная отправка/загрузка PNG в Telegram, VK, MAX, Instagram, Facebook, Threads, X, WhatsApp на физических iOS/Android не выполнена. Формат 9:16 может обрезаться в ленте X; подпись вставляется отдельно. Текущая проверка не заменяет предыдущую матрицу 36 PNG (см. ops/social-share-20261103/AUDIT.md) и не расширяет её до доставок.
